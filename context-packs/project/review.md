# Why the review action works the way it does

[Reviewing PRs in CI](../../docs/reference.md#reviewing-prs-in-ci) covers how to use it. This covers the choices that look like mistakes until you know the reason.

- **CI only reports, and every decision happens in the author's local run.** Each finding needs a person to decide it: a deviation can be fixed in the code or in the rule, and `pack-rule` waits for its wording to be approved. A run in CI can't wait for either. So it posts findings, and the author runs `/pack-review <PR>` locally, where the back-and-forth can take as long as it needs, with a checkout to change a pack at its source. Nothing in CI commits or pushes.
- **Finding and going through are two skills.** `pack-findings` turns a diff into findings, and `pack-review` goes through them with the user. CI runs only `pack-findings`, a local run on a PR CI reviewed runs only `pack-review`, and a local review runs both. `pack-review` loads `pack-findings` with the Skill tool, which can't load a skill that sets `disable-model-invocation`. So `pack-findings` is the one skill without it, and its description names who runs it, so an agent doesn't pick it for other reviews.
- **Hooks hold the answer until every doc is read.** The skill says to read every doc, but a run on Sonnet found all of them and read about half. `args.py` installs two hooks from `reads.py`, with the list from `context-packs docs` in `docs.txt`. One holds each subagent at `SubagentStop` until it has read the docs its prompt names. The other denies the `StructuredOutput` call, which is how the agent answers, until every doc was read by the agent or a finished subagent. A Stop hook would come too late, since the answer already exists by then. Reads are counted from the transcripts, by the lines each `Read` returned, so a doc counts only once all of it was read. The main transcript leaves out subagents' calls, so the subagent hook logs each subagent's transcript for the answer hook. Each hook gives up after sending the agent back three times, so a run that won't read a doc can't loop. The answer hook then lets the answer through, and the summary lists the docs still unread, since a partial review tells the author more than none. It says the skip is most likely pack-review's problem, since a doc on the list is one the tables show every agent.
- **`context-packs docs` reads the committed tables, not the packs.** Loading the packs fetches each one from git, and in CI a pack's origin can be a private repo the workflow's token can't read.
- **claude-code-action runs the agent, and the agent has no way to the PR.** The action installs Claude Code, handles auth, runs only for someone with write access, and restores `.claude/` from the base branch. The agent gets no MCP servers and no `gh`, so nothing it does reaches the PR. It has no shell: the action writes the diff and log to a new folder outside the checkout, and the agent reads them there and the checkout with `Read`, `Glob` and `Grep`, which `--restricted` confines to those two. Claude Code checks the paths a shell command reads, but not what it writes: an allowed `git log --format=format:<text> --output=<file>` wrote any text to any file, and git takes any unique prefix of `--output`, so no allow or deny rule on git commands is safe.
- **CI posts a summary, and no comments on the diff.** Threads on the diff need the agent to read the PR's comments and write to it, which takes a filter on whose comments it reads, a check on which threads it may write to, and cleaning both ways. The author's local run goes through every finding anyway, so the summary alone carries them. Threads would also stay open until a person resolves them: GitHub answers `Resource not accessible by integration` when the workflow's token resolves a thread, and the tokens that might be allowed, one with `contents: write` or a GitHub App's, can also push.
- **A script writes the summary, from the agent's validated answer.** `summary.py` runs in a step after the agent, with the answer claude-code-action checked against `findings.schema.json`.
- **The agent's findings lose only invisible characters and secrets before they're posted.** They appear only in the summary's JSON code block, where raw HTML, image syntax and links all show as written, so nothing in them is hidden from a person reading the block. Unicode format characters, such as zero-width spaces and direction overrides, don't show even there, so `sanitize.py` removes every one of them, rather than a list of known ones. Secrets are redacted by prefix. That matters because claude-code-action keeps its token in the agent's environment and in `.git/config`. The agent has no shell, and it's denied `Read` on `.git/`, which also stops `Grep` and `Glob` there, but it's confined only as far as its tools are.
- **The summary shows the agent's text only in its JSON.** A line of the agent's text rendered as Markdown could look different from what the local run reads, such as text in an HTML comment that doesn't render. In a code block, every character shows, so people and the local run see the same text. The summary's own text gives only the counts and the command to run.
- **The findings travel as JSON in a `<details>` block in the summary.** The author's run works through exactly what CI found, with only read access to the PR, and a person can open the block to see what it holds. A CI artifact would expire, and reviewing again locally would cost a second review and could find different things. Backticks are written as `\u0060`, so nothing in the agent's text can close the code fence. A comment holds at most 65,536 characters, so a summary that doesn't fit stops the run.
- **The local run reads the summary through one command `pack-review` gives in full.** Its `--jq` filter runs before the agent sees anything, and prints no comment's text but the summary's, since other comments can hold text written to steer the agent, and a check the agent ran after reading them would come too late. It reads every page, so a summary or a forged block past the first 30 comments isn't missed. It reads the summary's `bodyText`, GitHub's plain-text rendering, which leaves out HTML comments, image alt text, and link titles and URLs. It keeps the text of code, which is how the JSON comes through, and invisible characters, which is why `sanitize.py` removes them before posting.
- **pack-review's comments are told apart by the token's identity and a marker together.** Other workflows post with the same token, and anyone can type the marker. `viewerDidAuthor` says the token's identity wrote a comment without naming the bot, so it works with any token. `summary.py` adds the marker at the end, after the JSON block, so the agent's text can't put it there.
- **`claude_args` is built by `args.py`, with every `'` in JSON written as `\u0027`.** claude-code-action splits `claude_args` the way a shell would, so each value is quoted whole, and a value that's one pair of single quotes reads the same in any shell-style parser.
- **A run's log lists the agent's tool calls, but not what they returned.** Without it, nothing shows whether the agent read the packs, since claude-code-action keeps the transcript out of the log. Its full output can hold file contents and secrets, so `transcript.py` prints each call's input, and only whether its result was an error.
- **A summary is stale when the PR's head or base branch moved, not its base commit.** The base commit is the base branch's tip, so it moves whenever something merges there, while the diff from the merge base stays the same. Retargeting a PR, such as a stacked PR moving onto `main` after its parent merges, changes the diff with the head unchanged, so an edit that changes the base runs the review again. A force push to the base branch can change the diff without either moving, and goes unnoticed.
- **`summary.py` reads the PR's comments as one page of 100, and more is an error.** Reading more pages adds code no PR has needed, while a summary that missed its earlier one would post a second. The local run reads every page, since `gh` does that with one flag.
- **claude-code-action is pinned by commit.** The review relies on how it passes `claude_args`, the prompt and the token, and a tag can move.
